# Аудит безопасности, этап 8

Дата: 2026-09-16. Проверялся код бота, кабинета и схема базы на момент
коммита `8ca15dd` (конец этапа 7). Ниже что искали, что нашли и что сделали.

## Модель угроз

Кто может навредить и как:

- **Случайный или злой клиент в Telegram.** Заспамить бота, выжечь бюджет
  модели, протащить инструкции через сообщение, память или заявку, получить
  чужие данные.
- **Тот, кто нашёл кабинет в интернете.** Подобрать пароль, украсть сессию,
  отправить запрос от имени владельца с чужого сайта.
- **Тот, у кого утекла строка подключения бота или логи.** Прочитать в базе
  что-то кроме схемы школы, подделать историю миграций, вытащить токен бота.

## Что проверено и оказалось в порядке

- **SQL.** Все значения идут параметрами. Имя схемы подставляется текстом, но
  проходит проверку регулярным выражением. Динамический `update` заявки
  принимает только колонки из белого списка, имена колонок из ответа модели
  туда не попадают.
- **Права роли бота.** Только схема `school`, `public` и любые другие схемы
  закрыты, RLS включён на всех таблицах бота.
  Проверено подключением под ролью и тестом `test_bot_role_cannot_read_neighbour_schemas`.
- **Сессия кабинета.** Токен 32 случайных байта, в базе только его sha256,
  cookie `httpOnly`, `Secure`, `SameSite=Lax`, срок 7 дней, выход отзывает
  сессию. Пароль хранится хешем scrypt, в `.env` и в базе пароля нет.
- **Telegram.** Бот слушает только `message`, только личные чаты, только не
  ботов. Владелец определяется по `user.id`, который подтверждает сам
  Telegram, подделать его нельзя. Команды владельца недоступны клиентам.
- **Логи.** Текста сообщений клиентов нет, только id, тип, длина. Токен бота,
  пароль базы и ключ модели вырезаются из всех полей записи.
- **Модель.** Ответ проверяется по строгой JSON-схеме, метки источников
  сверяются с показанными кусками, ответ без источников превращается в
  передачу владельцу. Профиль и заявка принимают только поля из белых списков
  с ограничением длины. Память объявлена данными, а не инструкциями. Eval
  содержит пять кейсов на инъекции, включая через резюме.
- **Кабинет.** React экранирует вывод, `dangerouslySetInnerHTML` не
  используется, в базу кабинет не ходит.
- **Инфраструктура.** Секреты только в `.env`, файл в `.gitignore` и
  `.dockerignore`. Контейнер не под root. Зависимости с точными версиями.
  Порт бота слушает только `127.0.0.1`.

## Осознанно отложено

- **Лимит попыток входа живёт в памяти процесса.** Рестарт снимает
  блокировку. Экземпляр один, для владельца-одиночки этого достаточно.
- **Лимиты по IP нет:** бот не знает IP клиентов Telegram, а кабинет на
  этапе 9 окажется за Caddy, где лимит по IP ставится одной строкой.
- **Единственный владелец.** Ролей и прав в кабинете нет по границам MVP.
- **Ответ владельца без реплая** доставляется, если разговор один: осознанное
  решение, риск ошибиться адресатом принят.

## После этапа 9: Next.js и CVE-2025-55182

CVE-2025-55182 («React2Shell») это выполнение кода без аутентификации через
Server Actions Next.js, уязвимы версии ниже 15.5.7. Новый публичный домен
сканеры находят за минуты: каждое новое имя видно в прозрачных логах
сертификатов. Поэтому защита стоит в несколько слоёв.

1. Next закреплён точно на 15.5.25.
2. Caddy режет запросы с заголовком `Next-Action` и любой POST мимо `/api`:
   кабинет Server Actions не использует вообще, и эта преграда работает
   независимо от версии Next.
3. Кабинет работает под непривилегированным пользователем в минимальном образе
   `node:22-alpine`, и в его контейнере нет ни одной переменной с секретом:
   токен, строка базы и ключ модели живут только у бота.
4. Тесты: версия Next не ниже 15.5.7 и обе преграды присутствуют в Caddyfile.
